# 简历怎么写：把 P1 抓成主线

> 目标：一条主项目 + 一条能力佐证，让面试官在 90 秒内认定
> "这人做的是能评测的 AI 应用，不是 demo 拼装"。

---

## 1. 为什么选 P1 当主线

| | P1 注册路径判定 | P2 标签审核 | P3 卷宗一致性 |
|---|---|---|---|
| 数据来源 | **1,657 条官方裁决 + 1,917 节点真实目录** | 合成（缺陷人为埋入） | 合成（冲突人为埋入） |
| 指标性质 | 真实数据上的真实指标 | 引擎检出能力 | 引擎检出能力 |
| 指标规模 | n=355，带 95% CI | n=300 | n=180 |
| 技术深度 | 目录树遍历 / 时效路由 / 风险偏好 / 混合检索 | 规则表 + 三态 + 发布门禁 | 归一化 + 冲突判定 |
| 稀缺性 | **高**：公开数据里能挖出标注集的人不多 | 中 | 中 |
| 能否被证伪 | **能**：三次改进都被数据否掉 | 较弱 | 较弱 |

**决定性理由**：P1 是唯一一个"指标建立在真实数据上、且我自己能证明它还不够好"的模块。
这两点合起来，是面试里最难伪造的东西。

P2 的 100%、P3 的 100% 都来自合成集，只能证明"引擎按预期工作"，
不能证明"在真实场景有效"。**把合成集的 100% 放主线，一被追问就掉价。**

## 2. 简历条目（标准版，4 条）

> **医疗器械合规智能体套件 · 核心模块：注册路径判定**（个人项目）
> Python / FastAPI / LangGraph（自研确定性流水线）/ Milvus · 2026
>
> - **构建领域知识底座**：把药监局公开的 1,703 条分类目录转成 1,917 节点树（1,689 个可定类，
>   完整性校验零问题），并从 6,434 条分类界定结果中抽取 **1,657 条官方裁决**作为评测集
>   （19 个公告批次，2019–2026），解决了"没有标注数据"的启动问题
> - **判定与推理分离**：分类判定做成确定性流水线（目录树逐级收窄 → 类注排除 → 就高不就低），
>   LLM 只负责把产品描述翻译成结构化槽位；风险偏好做成 4 档可配置策略并随结果回传，
>   同一问题换策略得到不同类别时可解释原因
> - **建立三层评测口径**：端到端覆盖率 **77.4%**，355 条可判定样本上类别 Top-1 **69.6%**
>   （95% CI 64.6–74.1，Macro-F1 0.669）；检索层隔离实验（451 条）Top-1 62.3% vs 多数类基线 45.2%
> - **用评测证伪三条技术路线**：层级约束 / 交叉编码器重排 / 稠密向量，三者都把 Ⅲ 类召回抬高约 12pp，
>   但代价是 Ⅰ 类召回从 74.6% 塌到 31.1%；据此判定瓶颈不在检索质量，而在
>   **「管理类别不是文本相似度的函数」**，改为有监督分类方向

**技术栈行**（只写能撑住追问的）：
`Python / FastAPI / Pydantic / SQLAlchemy / 混合检索（BM25+向量+重排）/ 评测设计（分层抽样、Wilson 区间、成本矩阵）`

## 5. 必须准备好的三个追问

**Q1：69.6% 不高，这系统能用吗？**
> 不能直接上线，我把它定位成**评测基准 + 待改进基线**。它的价值是让后续任何改进都有参照系——
> 我试的三个方向都在它上面被否掉了。要上线，下一步是把检索式改成有监督分类，
> 因为我已经证明了瓶颈不在检索质量。

**Q2：为什么不用大模型直接判类别？**
> 试过路线，但没用模型拍板。原因有两个：一是**可复现性**——注册专员要能复算同一结论；
> 二是**可解释性**——结论必须能指到目录条目和规则。LLM 只做"口语 → 结构化槽位"这一步，
> 这一步它做得好且错了能发现。

**Q3：你的评测集怎么保证不泄漏？**
> 分类目录的「品名举例」在检索索引里，如果拿它当评测输入等于背答案——准确率会骗到接近 100%
> 然后一被问就崩。所以我用的是**分类界定结果**：那是企业送审时写的产品详情，
> 从不进任何目录，是真正的 held-out；而且送界定说明归类本身有争议，天然是难例。

## 6. 五个不要写

| 不要写 | 为什么 |
|---|---|
| ❌ "分类准确率 82%" | 那是 n=34 的小样本，95% 区间 66–92%，没有分辨力。全量是 69.6% |
| ❌ "准确率提升 X%" | 没有线上 A/B、没有基线版本对照，"提升"无从谈起 |
| ❌ "负责 XX 模块"（暗示团队分工） | 这是个人项目。写"核心模块 / 主攻方向"是诚实的，写"负责"会被追问团队规模 |
| ❌ 把 P2/P3 的合成集 100% 当成绩 | 只能说明引擎按预期工作。要写就写清"合成集"，并说明它衡量什么 |
| ❌ 罗列技术栈（LangGraph/FastAPI/Milvus/Neo4j/…） | 五个项目都这么写等于没写。只留能撑住追问的三四个 |

## 7. 如果目标岗位偏"合规产品/质量系统"

把主线换成 P2，因为它的**发布门禁**更贴产品岗口味：

> - 把 15 条必标项做成**条款驱动的规则表**（加一项只加一行数据，判定引擎不动），
>   AI 结论一律为草稿，须审核员署名确认后生成不可变快照（revision CAS，重复确认返回 409）
> - 三态判定（合规 / 违规 / **不可判定**）：识别置信度不足只允许判"不可判定"，
>   把"看不清"和"违规"分开——前者冤枉企业，后者放过风险
> - 合成集上缺陷检测 P/R 100%（结构化输入）/ 召回 80%（文本输入）；两者 20pp 差距
>   量化了视觉抽取层缺失的影响

主线换了，但第 2 节里的"数据底座 + 三层评测"仍然要挂在 P1 条目上作为佐证，
因为那是唯一有真实数据支撑的部分。

## 8. 一分钟自检

写完简历后问自己：

- [ ] 每条 bullet 里有没有一个**可核对的数字**？（n 是多少、区间多少、基线多少）
- [ ] 有没有一条 bullet 讲的是**判断**而不是功能？（"因此判定瓶颈不在检索"）
- [ ] 被追问"这个数字怎么来的"时，我能不能三句话讲清抽样方式和分母？
- [ ] 我有没有主动写下短板？（Ⅲ 类召回 43.6%、视觉未接、门控不可用）

最后一条是加分项，不是减分项——**主动承认边界的人被认为可靠，被问出来的人不会。**
